# ۰۳ · پارامترهای عملکردی و غیرعملکردی

> [!NOTE]
> اعداد «مقدار هدف» پیشنهاد تیم برای نمونهٔ آزمایشگاهی‌اند، نه مشخصهٔ تأییدشدهٔ کارخانه. ستون «نتیجهٔ اندازه‌گیری» از اجرای واقعی روی **داده‌ی مصنوعی** (seed=42، ۷ روز) به‌دست آمده است؛ جزئیات در [گزارش ارزیابی](06-lab-prototype-evaluation.md).

## ۱. پارامترهای عملکردی (Operational)

| پارامتر | مقدار پیشنهادی | توضیح |
|---|---|---|
| شبکهٔ زمانی مشترک | ۶۰ ثانیه | پیکربندی‌پذیر (`grid_period_s`) |
| دورهٔ نمونه‌برداری بومی | ۶۰ s (فرایند)، ۳۰۰ s (CO, NOx)، ساعتی (lab) | از رجیستری |
| gap کوتاه | ≤ ۵ دقیقه ⇒ درون‌یابی خطی | `short_gap_min` |
| gap متوسط | ۶ تا ۶۰ دقیقه ⇒ رگرسیون بین‌تگی + تصحیح مرزی | `medium_gap_min` |
| gap بلند | > ۶۰ دقیقه ⇒ **پر نمی‌شود** | تصمیم طراحی |
| آستانهٔ spike | ۶ واحد نویز (σ تفاضل مرتبهٔ اول، مقاوم) روی median پنجرهٔ ۹ نمونه‌ای | `hampel_*` |
| آستانهٔ flat-line | ۲۰ نمونهٔ یکسان پیاپی (۸ برای تگ‌های ۵ دقیقه‌ای) | `flatline_min_samples` |
| تحمل اتصال آزمایشگاه | ±۳۰ دقیقه | `lab_tolerance_min` |
| تبدیل واحد | از رجیستری، بدون تبدیل پنهان | خطا برای واحد ناشناخته |

## ۲. پارامترهای غیرعملکردی (Non-functional) و معیار پذیرش

| ویژگی | معیار پذیرش | نتیجهٔ نمونهٔ آزمایشگاهی |
|---|---|---|
| **قابلیت اطمینان** | هیچ ردیفی بی‌صدا حذف نشود؛ هر ردیف رد‌شده دلیل داشته باشد | ✅ ۳ ردیف معیوب ⇒ ۳ ردیف در `rejected` با دلیل |
| **ردیابی‌پذیری** | هر مقدار خروجی مشخص کند اصلی است یا جبران‌شده | ✅ ماسک `imputed` / `unrecoverable` |
| **صداقت داده** | داده‌ی gap بلند ساخته نشود | ✅ ۰٪ پرشدن در gap > ۶۰ دقیقه |
| **تکرارپذیری** | دو اجرا روی ورودی یکسان، خروجی یکسان | ✅ تست `test_pipeline_is_deterministic` |
| **سرعت پردازش** | ۳۰ روز داده (≈ ۴۰۰ هزار ردیف) کمتر از ۱ دقیقه روی یک لپ‌تاپ | ✅ ≈ ۳ ثانیه (Apple M2 Pro)؛ ⚠️ روی سخت‌افزار کارخانه UNVERIFIED |
| **حافظه** | کمتر از ۱ GB برای ۳۰ روز | ✅ ≈ ۲۷۰ MB |
| **قابلیت توسعه** | افزودن تگ/واحد بدون تغییر کد | ✅ فقط ویرایش `config/tags.yaml` |
| **امنیت داده** | پردازش آفلاین از فایل؛ بدون اتصال شبکه به سیستم کنترل | ✅ طراحی فقط‌خواندنی |
| **سازگاری با زیرساخت کارخانه** | اجرا بدون GPU و بدون اینترنت | ✅ فقط Python + pandas |
| **قابلیت نگهداری** | تست خودکار | ✅ ۱۴ تست |
| **امنیت اتصال زنده (OPC-UA)** | — | ⬜ خارج از دامنهٔ فاز ۱ |
| **نگهداری و پشتیبانی عملیاتی** | — | ⬜ فاز ۳ |

## ۳. محدودیت‌های زیرساختی (طبق پروپوزال: «سازگاری با محدودیت‌های زیرساختی کارخانه»)

- فرض: دسترسی فقط به **خروجی فایل** (CSV) از historian؛ نه دسترسی مستقیم به شبکهٔ کنترل. **UNVERIFIED**.
- فرض: ماشین اجرا ویندوز یا لینوکس معمولی با Python ۳٫۱۰+. **UNVERIFIED**.
- نیازهای ایمنی (safety): نمونه هیچ فرمانی به کنترل نمی‌فرستد؛ فقط داده می‌خواند و فایل می‌نویسد.
